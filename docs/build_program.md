# Maintainer Guide: Build-Time Program Subsystem (`ti_program_t`)

> **Audience:** Maintainers and contributors managing compiler lifecycle and build-time memory in TienInterpreter.

---

## 1. Struct: `ti_program_t` (`struct TI_PROGRAM_STRUCT`)

Defined in `src/include/ti_build_program.h` (opaque to hosts: `TienInterpreter.h` only declares the type):

```c
typedef struct TI_PROGRAM_STRUCT {
    ast_t       *root_ast;    /* Root AST node of the compiled program */
    alloc_hdr_t *alloc_list;  /* Dedicated allocation list tracking all build-time memory */
    char        *path;        /* Source path (owned copy on alloc_list), NULL if unknown (e.g. ti_run_string) */
} ti_program_t;
```

### Purpose & Field Contribution
`ti_program_t` encapsulates the compiled AST of a script alongside an isolated intrusive allocation list (`alloc_list`). All diagnostics and syntax errors are routed directly to the global error logging subsystem (`ti_log` / `ti_log_line`).

| Field | Type | Purpose & Contribution to Module Mechanics |
| :--- | :--- | :--- |
| `root_ast` | `ast_t *` | **Root AST Node:** Points to the root compound statement node of the compiled abstract syntax tree generated by `parser_parse()`. Borrowed by the runtime visitor for execution. |
| `alloc_list` | `alloc_hdr_t *` | **Build-Time Intrusive Allocations Head:** Head pointer of the intrusive doubly-linked list (`alloc_hdr_t`) tracking every build-time allocation (tokens, identifiers, AST nodes, parser/lexer structures). |
| `path` | `char *` | **Source Path:** Where the source came from, copied at compile time. Build errors name the file with it (`at <path>:<line>`), runtime errors raised by this program's code do too, the module loader receives the main script's path, and a script module's path is its identity (one module per path per runtime). |

---

## 2. Compiling

### `ti_program_compile(source_code, path, &status)`
1. Allocates the program and copies `path` onto its alloc list.
2. Lexes and parses its own copy of the source (the caller keeps `source_code`). The lexer borrows `prog->path`, so every lexer and parser message ends with `at <path>:<line>` (`at line <line>` without a path).
3. A build error is logged, `lexer_abort` jumps back, and the whole program is freed: `NULL` with `TI_ERR_SYNTAX`. Out of memory gives `TI_ERR_NO_MEMORY`, a `NULL` source `TI_ERR_INVALID_ARG`.

| Caller | `path` |
| :--- | :--- |
| `ti_compile(source)` | `NULL` |
| `ti_run_string(source)` | `NULL` |
| `ti_run_string_take(source, path)` | The host's path of the main script |
| `import` of a script module | The path returned by the module loader |

---

## 3. Ownership

| Program | Owner | Freed by |
| :--- | :--- | :--- |
| Main script | The host (or `ti_run_string*`) | `ti_program_free`, after `ti_execute` returned. The main namespace only borrows it (`rt->main_ns.prog`). |
| Script module | The module's namespace (`ns->prog`) | `ti_runtime_destroy`, after the namespace's variables and functions are freed. |

---

## 4. Memory Lifecycle & Batch Deallocation

### `ti_program_create(void)`
- Allocates the `ti_program_t` container using `tracked_calloc(NULL, 1, sizeof(ti_program_t))`.
- Initializes `root_ast`, `alloc_list` and `path` to `NULL`.

### `ti_program_free(ti_program_t *prog)`
- Performs instantaneous $O(N)$ batch deallocation of every build-time object allocated on `prog->alloc_list` via:
  ```c
  tracked_free_all(&prog->alloc_list);
  ```
- Because AST nodes, tokens, temporary strings and the path are linked to `prog->alloc_list`, manual recursive freeing of individual AST nodes is not required for clean memory recovery.
- Finally frees the program container itself via `tracked_free(NULL, prog)`.
